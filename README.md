# mebus — build in public

A small site for mebus: what it is building, why, and what progress looks like. It is a static Astro site: no database, no custom backend, no tracking cookies.

The product content comes from the build plan for an AI operating layer for Indian bus and logistics operators. Optional contact details live in `src/data/site.ts`, and the plan stages live in `src/data/roadmap.ts`. No customers, metrics, testimonials, or delivery dates are invented.

## Stack

- Astro 7 with static output
- TypeScript
- Plain CSS (system font stack)
- GSAP 3 with ScrollTrigger for the entrance timeline, scroll-linked hero drift, and staggered reveals (off for reduced motion)
- Markdown content collections for the build log
- Optional Formspree or Web3Forms contact form
- Optional Plausible or Cloudflare Web Analytics, off by default

Astro and GSAP are the only dependencies. RSS, the sitemap, and `robots.txt` are generated by small Astro endpoints.

## Run it locally

Requires Node `>=22.23.4`.

```bash
npm install
npm run dev
```

Open `http://localhost:4321`.

```bash
npm run build     # static site in dist/
npm run preview   # preview the production build
```

## Set up

1. Copy the environment template:

   ```bash
   cp .env.example .env
   ```

2. Fill in `SITE_URL`, the form endpoint, and anything else you need. See the table below.

3. Optionally add a LinkedIn URL or email in `src/data/site.ts`. Leave a field blank to hide it.

4. Review `src/data/roadmap.ts`. The seven entries are plan stages, not claimed delivery dates or completed work.

5. Add real build-log entries to `src/content/log/` when there is something true to report. The collection starts empty on purpose.

Optional settings are listed in [PLACEHOLDERS.md](./PLACEHOLDERS.md).

### Environment variables

| Variable | Required | Purpose |
| --- | --- | --- |
| `SITE_URL` | Yes for deploy | Public URL used for canonical links, Open Graph, RSS, sitemap, and `robots.txt`. No trailing slash. |
| `PUBLIC_FORM_ENDPOINT` | No | Optional override for the built-in Formspree endpoint. Use a different Formspree form URL or the Web3Forms endpoint. |
| `PUBLIC_FORM_ACCESS_KEY` | Web3Forms only | Web3Forms access key. It is public by design. Leave blank for Formspree. |
| `PUBLIC_ANALYTICS` | No | `off` (default), `plausible`, or `cloudflare`. |
| `PUBLIC_ANALYTICS_DOMAIN` | Plausible only | The domain registered with Plausible. |
| `PUBLIC_CLOUDFLARE_ANALYTICS_TOKEN` | Cloudflare only | Web Analytics beacon token. |

Astro bakes `PUBLIC_*` values into the static build. Set them in the host's build environment, not only in a local `.env`.

## Add a build-log entry

1. Copy the template:

   ```bash
   cp templates/build-log-entry.md src/content/log/my-update.md
   ```

2. Rename the file to the URL slug you want. `my-update.md` becomes `/log/my-update/`.

3. Fill in the frontmatter:

   ```yaml
   ---
   title: "What changed"
   date: 2026-11-02
   summary: "One or two plain sentences for the list and link previews."
   tags: ["csv", "imports"]
   draft: false
   # image: "/images/my-image.jpg"
   # imageAlt: "Describe what the image shows"
   ---
   ```

4. Write the entry in Markdown below the frontmatter.

5. Run `npm run build` or check `npm run dev`.

`draft: true` entries stay visible on the site with a Draft badge, but they are excluded from the RSS feed and sitemap and get a `noindex` meta tag. Set `draft: false` when an entry is ready.

For images, put the file in `public/images/` and use a path such as `/images/my-image.jpg`. The layout reserves a 16:9 area, so crop the image to that shape.

## Contact form

The form sits in the connect section immediately above the footer and posts directly to a form service. It has a honeypot (`_gotcha` plus Web3Forms' `botcheck`), client-side length limits, and clear success and error states. It uses the built-in Formspree endpoint by default.

**Formspree**

1. Create a form at [formspree.io](https://formspree.io).
2. To use a different form, set `PUBLIC_FORM_ENDPOINT` to its endpoint (`https://formspree.io/f/...`).
3. Leave `PUBLIC_FORM_ACCESS_KEY` empty.

**Web3Forms**

1. Create an access key at [web3forms.com](https://web3forms.com).
2. Set `PUBLIC_FORM_ENDPOINT=https://api.web3forms.com/submit`.
3. Set `PUBLIC_FORM_ACCESS_KEY` to the key.

The built-in endpoint is public information. If you switch to a different form service, update `form-action` and `connect-src` in `public/_headers` and `vercel.json`.

## Analytics

Off by default. Set `PUBLIC_ANALYTICS=plausible` with `PUBLIC_ANALYTICS_DOMAIN`, or `PUBLIC_ANALYTICS=cloudflare` with `PUBLIC_CLOUDFLARE_ANALYTICS_TOKEN`. Both are cookieless. The site sets no tracking cookies either way.

## Deploy

### Cloudflare Pages

1. Push the repo to GitHub.
2. In Cloudflare, go to **Workers & Pages → Create → Pages → Connect to Git**.
3. Choose the repo and use:
   - Framework preset: **Astro**
   - Build command: `npm run build`
   - Build output directory: `dist`
   - Root directory: `/`
   - Environment variable: `NODE_VERSION=22`
4. Add the environment variables from the table above for **Production** (and **Preview** if you want previews to work).
5. Deploy, then add your custom domain under **Custom domains**.
6. Set `SITE_URL` to the final URL (for example `https://your-domain.com`) and redeploy.

`public/_headers` is copied to `dist/_headers` and applied automatically by Cloudflare Pages. It sets the security headers and long-lived caching for `/_astro/*`.

### Vercel

1. Push the repo to GitHub.
2. In Vercel, **Add New → Project** and import the repo.
3. Vercel detects Astro. Use:
   - Build command: `npm run build`
   - Output directory: `dist`
4. Add the environment variables for Production, Preview, and Development.
5. Deploy, add the custom domain, then set `SITE_URL` to the final URL and redeploy.

`vercel.json` sets the same security headers, `trailingSlash: true`, and asset caching. The `public/_headers` file is harmless on Vercel.

## Security notes

- No secrets are committed. The built-in Formspree endpoint is public by design; analytics settings come from the environment.
- The production CSP allows only same-origin scripts/styles, the form service, and the chosen analytics provider. There are no inline scripts or style attributes in the generated HTML. GSAP sets transform and opacity through the CSSOM, which does not add inline style attributes.
- There is no database, login, server-side code, or user data storage in this repo.
- Do not add passenger names, phone numbers, or booking details to build-log entries or screenshots.
- If you change the form service or analytics host, update both `public/_headers` and `vercel.json`.

## Output

- `/` — single-page overview
- `/log/` — reverse-chronological log index
- `/log/<slug>/` — individual entries
- `/rss.xml` — feed of published entries (drafts excluded)
- `/sitemap.xml` — published pages only
- `/robots.txt` — points to the sitemap
- `/og.png` — 1200 × 630 social preview image

The RSS feed will be empty until at least one entry has `draft: false`. That is intentional: the collection starts empty.

## Social preview

`public/og.png` is a static 1200 × 630 image used for every page. If you change the name or the one-line description, replace it with a new image at the same dimensions. It is intentionally text-first, with no stock photography.

## Project structure

```text

  content/log/      Markdown build-log entries
  data/             personal details and roadmap data
  layouts/          base layout with SEO tags
  lib/              content queries, dates, XML escaping
  pages/            home, log pages, RSS, sitemap, robots, 404

templates/          new-entry template
```

## Lighthouse

Run against the production build with Chrome installed:

```bash
npm run build
npm run preview
npx lighthouse http://localhost:4321/ --view
```

Do not copy old scores into this file after a design change. Run Lighthouse against the current build and check `/`, `/log/`, and `/404.html` directly. Confirm the accessibility score, the strict CSP, and the reduced-motion path before publishing.

GSAP and ScrollTrigger are the largest client-side asset. Motion only changes transform and opacity, and the whole motion layer is skipped when `prefers-reduced-motion` is set. The hero also swaps to a static image in that case.

## Notes

- The plan is a plan, not a claim. The seven numbered stages do not imply completed work or delivery dates.
- The build-log collection is empty until there is something real to publish. The home-page log section and the contact section stay hidden until their content is configured.
- The site is light-only by design. It has no theme toggle.
